## 三方一致警告 (按严重度排)

### 🔴 P0 风险: Selena 接受度未知
两家都标"高概率 + 高严重度". 11 件改动让 app 比之前重很多. **如果 Selena rage quit, 全部 ship 价值归 0**.
- 缓解: 跟 Selena 协商先开哪些, feature flag 个别 OFF

### 🟡 P1 缺口: 竖式专项训练真缺
**两家都说"绝对真 gap, 不是 over-engineering"**. 期中失分大头是进位/退位错, 估算救不了底层 mechanics.
- 设计共识 (取两家整合):
  - 5 分钟"竖式工坊" mini-game
  - 3 难度层: ① 找别人错 (类似错题侦探) ② 填空式 (给框架填数字+进位) ③ 完整自己写
  - 强制专门的"进位/退位 小方块" 训练肌肉记忆
  - 错题 24h/3d/7d 回炉 (真间隔重复)

### 🟡 P1 缺口: 没数据监控
我用"功能 ship 了" 当成果. 但**没数据看触发率 / 完成率 / drop-off**. 评审 B 强调:
- 触发率: estimation 多少 % 题触发, multi-step 多少, etc.
- 完成率: estimation 3 phase 走完率, multi-step 4 phase 全对率
- drop-off: 每个 phase 哪步用户退出
- 单题耗时变化: 真变长 (System-2 启动) vs 没变 (Selena 在快点跳过 friction)

### 🟢 P2 修正: 我对"直接解决"过于乐观
- "单位换算直接解决" — **不对**, 必须 Selena 真做完 4 节 + 在应用题里迁移才算
- "应用题 4 步法直接解决" — **不对**, 还要看完成率 + 留空率真下降
- "选择题转填空直接解决" — 仍然部分对, 但复杂选择题还能猜
