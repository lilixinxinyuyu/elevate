# 题库质量四原则（rock-solid · 出题与质检共用）

> 这是出题模型和质检模型共享的**唯一**判定依据。优先级高于一切训练偏好和习惯。
> 出题前过一遍这 4 条；质检时按这 4 条出 verdict。

四原则故意只有 4 条 —— 多了 LLM 注意力会被切散，新场景反而 generalize 不动。所有 vfail 模式都应该能映射到这 4 条之一；如果不能，去精炼现有原则的"判定细节"，**不要**加 P5。

---

## P1：题面纯净 — 学生看到的字段不带元注解 + stem 不嵌入 filler

**核心**：学生 UI 渲染路径上的所有字段（`stem` / `subquestions[].clues` / `subquestions[].prompt` / `options[].text` / `hints[].text` / `feedback_correct` / `feedback_wrong`）都是"老师在讲台上说的话"。元信息（哪个错、为什么错、归类是什么）属于"老师备课本"，永不进 UI。

**判定方法**：把这段文字念给 4 年级 Selena 听，**不变味**才合格。一旦念出来等于直接告诉她"哪个不选 / 哪个无关 / 该用什么思路"，就 fail。

### P1.5：stem 极简，不嵌入无关人物/句子

word_problem_lab 的 stem 应该**只描述数学情境**，**不要**嵌入无关 filler（如"技术员赵叔叔说设备运行稳定"、"水果店在市中心"、"今年是植树节"等社交/装饰性句子）。

**原因**：
1. clue_pick 阶段已经给学生 4-5 条 clue 让她自己判断哪些有用。无关信息**应该放 clues**，不应该 stem 重复。
2. stem 多一句无关，Selena 读题时间多 3-5 秒。4 年级读字慢，filler 是认知负担。

**反例（v0.31.80 实际看到）**：
```
stem: "工厂一台机器每分钟生产零件 2.75 个，今天上午工作了 36 分钟，下午工作了 24 分钟。
       技术员赵叔叔说设备运行稳定。今天一共生产多少个零件？"
                                          ↑ 这句应放 clues 或删除
```

**正例**：
```
stem: "工厂一台机器每分钟生产零件 2.75 个，今天上午工作了 36 分钟，下午工作了 24 分钟。
       今天一共生产多少个零件？"
clues: [
  "每分钟生产零件 2.75 个",
  "上午工作了 36 分钟",
  "下午工作了 24 分钟",
  "技术员赵叔叔说设备运行稳定",   ← 无关 filler 在这里，让学生自己判断
  "零件是金属做的"
]
correct: [0, 1, 2]
```

**判定**：stem 里如果有"X 叔叔说"、"今年是 Y 节"、"地点在 Z"、"今天天气 W"等不进入计算的句子 → 移到 clues 数组。

### 反例（必须 reject）

```jsonc
// ❌ clue 文本里挂元注解
"clues": [
  "苹果树和橘子树共 156 棵",
  "果园占地 2 公顷（无关）",            // ← "（无关）" 直接告诉学生别选
  "设橘子树为 x（解题设定，非已知）"      // ← "（非已知）" 同上
]

// ❌ option 上挂 errorTag 这种 meta 字段
"options": [
  { "id": "A", "text": "x + 6x = 156", "correct": true },
  { "id": "B", "text": "6x - x = 156", "correct": false,
    "errorTag": "sum_vs_difference_confusion" }   // ← errorTag 不能在 student-visible 字段
]

// ❌ hint 文本里直接给关键运算
"hints": [{ "text": "156 ÷ 7 除不尽，用小数表示", ... }]
//                ↑ 这是答案不是 hint，把核心步骤暴露了

// ❌ feedback_wrong 复述"错答路径"
"feedback_wrong": "再读一遍，注意别用差倍式 6x - x = 156"
//                              ↑ 直接点名错答的具体形式
```

### 正例

```jsonc
// ✅ clue 是中性陈述，让学生自己判断哪些有用
"clues": [
  "苹果树和橘子树共 156 棵",
  "苹果树是橘子树的 6 倍",
  "果园占地 2 公顷",                  // ← 不挂"（无关）"标签，让学生判断
  "果树都是三年生"
]

// ✅ errorTag 信息保留在 admin-only 字段（带 _internal_ 前缀），不在 options 上
"options": [
  { "id": "A", "text": "x + 6x = 156", "correct": true },
  { "id": "B", "text": "6x - x = 156", "correct": false }
],
"_internal_option_diagnostics": [
  { "id": "B", "errorTag": "sum_vs_difference_confusion" }
]

// ✅ hint 给思路方向，不给关键运算结果
"hints": [{ "text": "把橘子树看成 1 份，苹果树看成 6 份，一共多少份？", ... }]

// ✅ feedback 鼓励 + 概念引导，不复述错答
"feedback_wrong": "再仔细读一次「一共有」这三个字提示什么关系？"
```

## P2：数学闭合 + 现实合常识

**核心**：质检模型自己跑一遍这两步：
1. **数学闭合**：把题面给的关系列方程，能在题目要求的数域里有解？（整数情境必须整除；小数情境最多 2 位小数）
2. **现实约束**：答案在该 unit 下合常识？（果树 / 人数 / 本数必须整数；钱数 ≥ 0；距离 / 时间合理；不能出现"小数棵"或"负年龄"）

**判定方法**：在 verdict 里写"我把数学跑了一遍：x = ?，是否整数 / 是否合常识"。

### 反例

- "苹果树是橘子树的 6 倍，共 156 棵" → 7x = 156 → x ≈ 22.29 棵 ❌（果树不能小数）
- "正方形周长 25 厘米" → 边长 6.25 厘米（4 年级范围 OK，但若要求"用整数厘米"就 fail）
- "Selena 比妹妹大 -3 岁" → 年龄差不能负

### 正例

- "苹果树是橘子树的 6 倍，共 154 棵" → 7x = 154 → x = 22 ✓
- "正方形周长 24 厘米" → 边长 6 厘米 ✓

**重要**：generation 模型出题前必须自查"我设计的数字能整除 / 答案合常识吗"。reject 由 generation 自己提前避免，比 judge 后筛 cheaper。

## P3：干扰项独立 — 不能靠"题中数字的衍生"凑数

**核心**：每个 distractor 必须代表"4 年级 Selena 真实会犯的一种具体错误"，每个 distractor 都要能用一句话说清"这个数从哪种误解来"。

**判定方法**：对每个干扰项问："这个值，学生用什么走偏的思路会算出来？" 答不上来或者答的是"题中另一个量的数值" → reject。

### 反例

题：x + 6x = 156，正答 22。
- distractor `133.71` ❌ —— 这是 6x 的值（苹果树棵数）。学生看到一个奇葩小数 vs 三个整数，秒识别"这肯定不是 x"，等于排除一个 + 暗示正答也是奇葩小数（22.29）。
- distractor `6` ❌ —— 题面给的"6 倍"的 6，原样塞进选项 = 学生最先排除的。
- distractor `156` ❌ —— 题面给的总数，原样塞进选项 = 同上。

### 正例

- distractor `26` ✓ —— 来源："总数 ÷ 倍数 = 156 ÷ 6 = 26"，是把和倍当差倍 / 漏 +1 的典型错。
- distractor `20` ✓ —— 来源："总数 ÷ (倍数+2) = 156 ÷ 8 = 19.5 ≈ 20"，把"+1"算成"+2"。
- distractor `18` ✓ —— 来源："倍数 × 3 = 18"，凭直觉乱猜小整数。

四个选项 1 正 + 3 错，每个错都"看起来合理 + 走的是真实学生会走的思路"。

## P4：skill 真考 —— 不能蒙对、不能取巧

**核心**：题目必须迫使学生**用那个 skill 的核心思路**才能做出来。能用排除法、量级估算、看选项长相秒杀的题，等于没考 skill。

**判定方法**：把题给一个"会基础算术但不会该 skill"的孩子做，能不能凭运气 / 量级 / 选项相对长度蒙对一半以上？能蒙对 → fail。

### 反例

- 选项 `[22, 22.29, 26, 134]`：看到 22.29 这种奇葩小数立刻排除，134 是另一个量的衍生立刻排除，剩下 22 / 26 二选一。**未列方程也能 50% 蒙对**。
- 数学倍数题选项 `[1, 2, 1000000, 22]`：量级唯一合理的 22。**直接看出**，不用计算。
- 选择"最佳数量关系"，4 个选项里只有 1 个是加号、其他都是减号 → 题面"一共"立刻暴露。

### 正例

- 选项 `[18, 20, 22, 26]`：4 个量级一致，区分度只来自"是否抓住了 7 份的关系"。
- 数量关系 4 选项：`x + 6x = 156` / `6x - x = 156` / `x + 6 = 156` / `x × 6 = 156`，都是"看起来合理的设方程方式"，必须真懂"和倍 / 差倍 / 数量积"才能选对。

## 共用提示

- 每条原则**违反 = 该题应被 reject**（severity 4-5），但保留路径如下：
  - **P1 违反** = 一定 reject（题面 leak 不可修，数据已 contam）
  - **P2 违反** = 一定 reject（数学错就是错，不能"修 hint" 救活）
  - **P3 违反** = borderline（可以重新设计 distractor 救活）
  - **P4 违反** = borderline（可以调 distractor 区分度救活）
- 出题时**4 条同时考虑**，不分先后。
- 如果某新出现的 vfail 模式 4 条都覆盖不到，先想想能不能精炼现有原则的"判定细节"；不要轻易加 P5。
